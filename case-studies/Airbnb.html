Project Overview

Airbnb is a full-stack clone of Airbnb, built as three connected parts: a public-facing guest site, an admin dashboard for hosts, and a Node.js/Express/MongoDB backend powering both. Guests can browse listings by category and location, view detailed listing pages with an interactive map and live cost calculator, and make reservations. Hosts get a JWT-authenticated dashboard to create, update, and delete listings with real image uploads.

The Problem

Recreating Airbnb's core booking flow end-to-end — not just the visual layout, but the underlying logic: dynamic pricing that accounts for nights, weekly discounts, cleaning and service fees, and occupancy taxes; location-based search with an accurate map; and a secure, role-aware admin system for managing listings and reservations, all connected to a real database rather than static mock data.

The Solution

I built a three-part application: a React/Vite frontend for guests, a separate React admin dashboard, and a Node/Express/MongoDB REST API connecting both. Listings, users, and reservations are stored in MongoDB via Mongoose schemas, with JWT protecting all admin routes. The frontend integrates Leaflet and OpenStreetMap for interactive, no-API-key location maps, and a live cost calculator that recalculates totals as guests change dates and guest count.

My Role

I was responsible for the full build — planning the three-part architecture, designing and building the UI, implementing the backend API and database schemas, wiring up authentication, debugging production issues, and deploying the finished application to Render.

Challenges & How I Solved Them

Connecting the Frontend, Backend and Database

One of the biggest challenges was making sure the React frontend, Node/Express backend, and MongoDB database worked together reliably. Data that worked correctly in one part of the application could still fail when passed between layers.

I solved this by testing the data flow step by step, checking API requests and responses, validating MongoDB schemas, and using consistent data structures between the frontend and backend. This helped me identify whether an issue was coming from the UI, API, or database instead of trying to fix everything at once.

Building the Dynamic Booking Cost Calculator

Calculating the booking total was more complex than displaying a fixed price. The total needed to respond to the number of nights, number of guests, cleaning fees, service fees, occupancy taxes, and applicable discounts.

I solved this by breaking the calculation into smaller parts and updating the total whenever the selected dates or guest count changed. I also tested different combinations of dates and guests to make sure the displayed total remained consistent with the booking information.

Handling Location Data and Interactive Maps

Another challenge was displaying listing locations accurately on an interactive map without relying on a paid mapping API. I needed the listing data and map coordinates to stay in sync so that users could understand where a property was located.

I solved this by implementing Leaflet with OpenStreetMap and connecting the map to the listing data. This allowed me to display interactive markers without requiring a paid mapping API.

Authentication and Protected Admin Features

Protecting the admin functionality was another challenge because sensitive operations such as creating, updating, and deleting listings should not be accessible to every user.

I implemented JWT-based authentication and protected the relevant API routes. The frontend also uses authentication state to control access to dashboard functionality.

Debugging Production and Deployment Issues

Getting the application working locally was only part of the challenge. Deploying the frontend, admin dashboard, and backend introduced additional issues around environment variables, API URLs, CORS, and communication between the deployed services.

I solved these problems by testing each deployed service separately, checking browser and server logs, verifying environment variables, and tracing failed requests between the frontend and backend. This helped me understand how the different parts needed to communicate in a production environment.
