Banele Airbnb

📌 Project Overview

Banele Airbnb is a full-stack clone of Airbnb, built as three connected parts: a public-facing guest site, an admin dashboard for hosts, and a Node.js/Express/MongoDB backend powering both. Guests can browse listings by category and location, view detailed listing pages with an interactive map and live cost calculator, and make reservations. Hosts get a JWT-authenticated dashboard to create, update, and delete listings with real image uploads.

🎯 The Problem

Recreating Airbnb's core booking flow end-to-end — not just the visual layout, but the underlying logic: dynamic pricing that accounts for nights, weekly discounts, cleaning and service fees, and occupancy taxes; location-based search with an accurate map; and a secure, role-aware admin system for managing listings and reservations, all connected to a real database rather than static mock data.

💡 The Solution

I built a three-part application: a React/Vite frontend for guests, a separate React admin dashboard, and a Node/Express/MongoDB REST API connecting both. Listings, users, and reservations are stored in MongoDB via Mongoose schemas, with JWT protecting all admin routes. The frontend integrates Leaflet and OpenStreetMap for interactive, no-API-key location maps, and a live cost calculator that recalculates totals as guests change dates and guest count.

👤 My Role

I was responsible for the full build — planning the three-part architecture, designing and building the UI, implementing the backend API and database schemas, wiring up authentication, debugging production issues, and deploying the finished application to Render.

✨ Key Features

  • Category and location-based listing search and filtering
  • Interactive map on listing search results and individual listing pages (Leaflet/OpenStreetMap)
  • Live cost calculator: nightly rate, weekly discount, cleaning fee, service fee, occupancy taxes
  • Reservation creation, stored in MongoDB
  • JWT-authenticated admin dashboard with role-aware access
  • Create, view, update, and delete listings with real image upload
  • Reservation management for hosts
  • Responsive layouts across the public site and admin dashboard

🛠️ Development Process

I started by defining the project structure across three apps — public frontend, admin dashboard, and backend — each with its own clear responsibilities. I built the backend's Mongoose schemas and CRUD routes for accommodations, reservations, and users first, then layered JWT authentication and middleware on top before connecting the frontend.

Once the core CRUD flows were working end-to-end, I added the map feature, the live cost calculator, and image upload, testing each addition against the live app before moving to deployment on Render and MongoDB Atlas.

🧠 Technical Decisions

I chose Leaflet with OpenStreetMap tiles over Google Maps to avoid requiring an API key, keeping the project fully self-contained and free to run. Listing coordinates are resolved from each listing's location text via a lookup table rather than a paid geocoding service, which was a deliberate trade-off between accuracy and simplicity for this scale of project.

I split the codebase into a clearly separated three-app structure (frontend, admin dashboard, backend) so each piece could be developed, tested, and reasoned about independently, rather than one large mixed application.

⚠️ Challenges and Solutions

MongoDB connection failing with a DNS error. The standard mongodb+srv:// connection string relies on a DNS SRV lookup that was being blocked on my network. I switched to Atlas's non-SRV connection string, which lists servers directly and bypasses the SRV lookup entirely.
Server crashing on any database hiccup. The original connection code called process.exit(1) on any MongoDB error, killing the entire server instead of returning a clean error response. I replaced it with a re-thrown error handled by Express's error middleware, so a connection issue degrades gracefully instead of taking the whole app down.
Leaflet's zoom controls rendering above the sticky header. Leaflet's internal z-index values escaped their container and floated above the page header on scroll. I wrapped each map in its own CSS stacking context (isolate), containing Leaflet's internal layering so it can never climb above the rest of the UI.
Duplicate, dead backend code. An earlier iteration of the project had left two parallel sets of models, controllers, and routes, only one of which was actually wired into the running server. I traced the dependency graph, confirmed the unused set had zero live references, and removed it — bringing the backend back in line with the intended project structure.
A double-click race condition on the listing form. A rapid double-click could land on the "Next" and "Publish" buttons in the same screen position in quick succession, submitting the form before an image was chosen. I added a timestamp guard inside the submit handler itself, rejecting any submission that follows a step change within 600ms.

🧪 Testing

I manually tested the full reservation flow end-to-end — browsing, filtering, viewing a listing, adjusting the cost calculator, and reserving — as well as the full admin CRUD cycle for listings (create with image upload, view, update, delete) and authentication (valid login, invalid password, malformed email). I also tested the deployed production build on Render against the live MongoDB Atlas database to confirm behaviour matched local development.

📈 Project Outcome

The final result is a deployed, three-part full-stack application that demonstrates end-to-end ownership of a real-world product: database design, a secure authenticated API, an interactive map integration, and a polished, responsive UI across both a public site and an admin dashboard — taken from a rough build through real production debugging to a live deployment.

🌱 What I Learned

  • Designing a multi-app project structure with clear separation of concerns
  • Diagnosing and fixing real production issues (DNS/connection failures, race conditions, dead code)
  • Integrating a mapping library (Leaflet) without relying on a paid API
  • Managing CSS stacking contexts and z-index conflicts in a real layout
  • JWT-based authentication and protecting routes with middleware
  • Deploying a full-stack app with a live database to Render and MongoDB Atlas

🚀 Future Improvements
