Google Keep Clone

React Application Case Study

Project Overview

This project is a responsive Google Keep-inspired note-taking application built with React and Vite. It allows users to create, edit, search, organise, archive, and delete notes through a familiar and easy-to-use interface.

React Vite JavaScript CSS Local Storage Responsive Design

The Problem Statement

A useful note-taking application must make it quick to capture information while still helping users organise and find it later. The main challenge was managing several note states and features without making the interface feel complicated, while also keeping the experience consistent on desktop and mobile.

My Role

I worked as the frontend developer responsible for migrating the original HTML, CSS, and JavaScript application to React, dividing the interface into reusable components, managing application state, and implementing the responsive user experience.

Core Features

  • Create and edit notes through a focused note modal
  • Search notes instantly by title or content
  • Pin important notes and apply custom note colours
  • Organise notes with category tags and reminders
  • Archive and unarchive notes
  • Move notes to the bin, restore them, or delete them permanently
  • Switch between light and dark themes
  • Use the application across desktop and mobile screen sizes

Development Process

  • Reviewed the original vanilla JavaScript application and its behaviours
  • Set up the React project using Vite
  • Split the interface into reusable components
  • Moved DOM-based logic into React state, props, and event handlers
  • Added advanced organisation and personalisation features
  • Tested layouts and interactions across different screen sizes
  • Prepared and deployed the production build on Netlify

Implementation

The application uses React components for the header, sidebar, note composer, notes grid, note cards, and editing modal. React state controls the active view, search results, note actions, and interface updates. Notes are saved in local storage so they remain available after the browser is refreshed, while the selected theme is stored separately.

Challenges

The biggest challenge was keeping every note action predictable across the Notes, Archive, and Bin views. Migrating the project to React also required replacing direct DOM manipulation with state-driven rendering. I solved this by centralising note updates and giving each component a clear responsibility.

Outcome

The final result is a deployed, responsive React application that goes beyond a visual clone. It demonstrates component-based development, state management, browser persistence, responsive design, and the ability to extend an existing project with useful real-world features.
